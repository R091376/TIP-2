# Deploy TIP-2 on Render (split services)

Blueprint file: [`render.yaml`](../render.yaml) at repo root.

## Services

| Service | Type | Root | URL shape |
|---------|------|------|-----------|
| `tip2-api` | Web (Python) | `backend/` | `https://tip2-api.onrender.com` |
| `tip2-web` | Static (Vite) | `frontend/` | `https://tip2-web.onrender.com` |

## One-time Blueprint setup

1. Push `main` to GitHub (`R091376/TIP-2`).
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint** → select repo.
3. When prompted, set **sync: false** secrets:

| Variable | Service | Value |
|----------|---------|--------|
| `DATABASE_URL` | tip2-api | Neon URL (`postgresql+psycopg://…?sslmode=require` or `postgresql://…?sslmode=require`) |
| `UPSTOX_ACCESS_TOKEN` | tip2-api | Long-lived Upstox **access token** (not app key) |
| `CORS_ALLOWED_ORIGINS` | tip2-api | **Required for login.** Blueprint sets `https://tip2-web.onrender.com,http://localhost:5173`. If you rename the FE service, update this to the exact FE origin. |
| `VITE_API_BASE_URL` | tip2-web | Optional. If empty, build uses `https://$API_HOST` from the API service |
| `VITE_FEATURE_STARTUP_READY` | tip2-web | Optional. Default **ON**. Staged UI: Backend API → Postgres → Session (with Retry on timeout). Set `false` to restore simple “Checking session…”. |

`SESSION_SECRET` is auto-generated by the Blueprint.

## Deploy order

1. Apply Blueprint (API + static site create).
2. Confirm API health: `GET https://tip2-api.onrender.com/api/health`.
3. Set `CORS_ALLOWED_ORIGINS` to the real FE origin if not set.
4. **Redeploy tip2-web** so Vite bakes `VITE_API_BASE_URL` (build-time).
5. Open FE → login `admin` / `admin` (or your passwords).

## Local vs production

| | Local | Render split |
|--|--------|----------------|
| FE API calls | relative `/api` + Vite proxy | `VITE_API_BASE_URL` → API origin |
| FE WebSocket | same host `/ws/live` | `wss://tip2-api…/ws/live` |
| CORS | `http://localhost:5173` | FE origin |
| Cookie SameSite | `lax` | `none` + Secure |

## Code entry points

- Backend CORS / cookies: `backend/app/config.py`, `backend/app/main.py`
- FE base URL: `frontend/src/config.ts` → used by `http.ts`, `liveSocket.ts`

## If login works then chart is empty with auth error

Typical cause: **session cookie not stored** on cross-site FE → API (split Render services).

1. Login returns 200 + user JSON, so the UI navigates to the chart.
2. Browser never keeps `TIPSESSION` (SameSite / Secure / CORS).
3. Chart calls (`/api/watchlist`, etc.) return **401** → empty chart + red banner.

Deploy checklist:

| Env (tip2-api) | Value |
|----------------|--------|
| `SESSION_COOKIE_SAMESITE` | `none` |
| `SESSION_COOKIE_HTTPS_ONLY` | `true` |
| `CORS_ALLOWED_ORIGINS` | exact FE origin, e.g. `https://tip2-web.onrender.com` (no trailing slash) |

The frontend now **verifies `/api/auth/me` after login** and will stay on the login page with a clear message if the cookie was not kept. Mid-session 401s clear the client session and return you to login.

## If FE shows blank / Not Found

1. **Dashboard → tip2-web → Logs** — confirm `npm run build` produced `dist/assets/*`.
2. **Environment** on tip2-api:  
   `CORS_ALLOWED_ORIGINS=https://tip2-web.onrender.com`  
   (exact FE origin, no trailing slash)
3. **Environment** on tip2-web:  
   `VITE_API_BASE_URL=https://tip2-api.onrender.com` then **Manual Deploy → Clear build cache & deploy**.
4. SPA rewrite source must be quoted as `"/*"` in `render.yaml` (unquoted `/*` breaks YAML).

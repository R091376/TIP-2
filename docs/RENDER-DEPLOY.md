# Deploy TIP-2 on Render (same-origin SPA + API)

Blueprint file: [`render.yaml`](../render.yaml) at repo root.

## Why same-origin?

Split hosting (`tip2-web` + `tip2-api`) makes the session cookie **third-party**.
Browsers (especially mobile Chrome/Safari) often **block** third-party cookies even when:

- `SESSION_COOKIE_SAMESITE=none`
- `SESSION_COOKIE_HTTPS_ONLY=true`
- `CORS_ALLOWED_ORIGINS` is correct

Industry guidance for **first-party login** is to keep SPA and API on the **same site**
so `TIPSESSION` is first-party (`SameSite=Lax` works). See Google Privacy Sandbox
[third-party cookie restrictions](https://privacysandbox.google.com/cookies/prepare/overview).

**Primary app URL:** `https://tip2-api.onrender.com/`  
(API + React app on one origin; login works on desktop and mobile.)

`tip2-web` only redirects to the API host so old bookmarks keep working.

## Services

| Service | Type | Role |
|---------|------|------|
| `tip2-api` | Web (Python) | FastAPI **and** built Vite SPA from `backend/static` |
| `tip2-web` | Static | Redirect → `https://tip2-api.onrender.com/` |

## One-time Blueprint / re-sync

1. Push `main` to GitHub.
2. [Render Dashboard](https://dashboard.render.com) → **New → Blueprint**, **or** open existing Blueprint → **Sync** so live services pick up `render.yaml` (build command, `rootDir`, cookie flags).
3. Set **sync: false** secrets if prompted:

| Variable | Service | Value |
|----------|---------|--------|
| `DATABASE_URL` | tip2-api | Neon URL (`postgresql+psycopg://…?sslmode=require` or `postgresql://…?sslmode=require`) |
| `UPSTOX_ACCESS_TOKEN` | tip2-api | Long-lived Upstox **access token** (not app key) |

`SESSION_SECRET` is auto-generated by the Blueprint.

### Already set by `render.yaml` (after sync)

| Variable | Value | Why |
|----------|--------|-----|
| `TIP_WATCHLIST_STORE` | `postgres` | Use Neon |
| `SESSION_COOKIE_SAMESITE` | `lax` | First-party cookie on API host |
| `SESSION_COOKIE_HTTPS_ONLY` | `true` | HTTPS only |
| `CORS_ALLOWED_ORIGINS` | localhost only | Local Vite → prod API optional; SPA is same-origin |
| `PYTHON_VERSION` | 3.12.8 | Runtime pin |
| start | `cd backend && uvicorn … --workers 1` | Live feed is process-local |
| build | Node + Vite build → `backend/static` | Same-origin SPA |

### If you already have services (Blueprint once, never synced)

Update **tip2-api** in Dashboard (Settings + Environment) to match blueprint:

1. **Root Directory:** empty / `.` (repo root), **not** `backend`
2. **Build Command:** copy from current `render.yaml` `buildCommand` (installs Node, builds FE, copies to `backend/static`)
3. **Start Command:** `cd backend && uvicorn app.main:app --host 0.0.0.0 --port $PORT --workers 1`
4. **Env:**
   - `SESSION_COOKIE_SAMESITE=lax`
   - `SESSION_COOKIE_HTTPS_ONLY=true`
   - `CORS_ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173` (optional for local)
5. **Manual Deploy** tip2-api (clear build cache if SPA still missing)
6. Open **`https://tip2-api.onrender.com/`** (not tip2-web for daily use)

## Deploy smoke checklist

- [ ] `GET https://tip2-api.onrender.com/api/health` → `{"status":"UP",…}`
- [ ] `GET https://tip2-api.onrender.com/` → **HTML** app shell (not JSON `tip2-api` note)
- [ ] JS under `/assets/` returns 200
- [ ] Login on **phone and desktop** (first-party cookie)
- [ ] Watchlist + candles + live WS (`wss://tip2-api…/ws/live`)
- [ ] `https://tip2-web.onrender.com/` redirects to API host

## Local vs production

| | Local | Render (same-origin) |
|--|--------|----------------------|
| FE | Vite `http://localhost:5173` + proxy | Served by FastAPI at `/` |
| API calls | relative `/api` via proxy | relative `/api` same host |
| WebSocket | Vite proxies `/ws` | same host `/ws/live` |
| Cookie SameSite | `lax` | `lax` + Secure |
| CORS | localhost | not needed for the SPA |

## Code entry points

- SPA mount: `backend/app/spa.py`, `backend/app/main.py`
- Cookie / CORS: `backend/app/config.py`
- FE base URL: leave `VITE_API_BASE_URL` empty for same-origin (`frontend/src/config.ts`)

## If login still fails with cookie message

1. Confirm you open **`https://tip2-api.onrender.com/`**, not a cross-origin static site calling the API.
2. Confirm deploy logs show `SPA mounted from …` and `same_site=lax`.
3. Confirm `backend/static/index.html` exists in the build (`test -f static/index.html` in buildCommand).
4. Hard-refresh / clear site data for the API host on the phone.
